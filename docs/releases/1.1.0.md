# 1.1.0 — release notes

This file is the hand-written input for the 1.1.0 GitHub release. `CHANGELOG.md` on `main` is
generated by semantic-release from the commit history, which also computes the version (a
minor: the release carries `feat` and `fix` commits and no breaking-change footer). Upgrade
instructions: [`docs/upgrading-to-1.1.md`](../upgrading-to-1.1.md).

## Security

1.1.0 fixes the issues described in the GitHub security advisories published with this
release (GHSA-8p84-pc7q-69jr and the related advisories on the repository's Security tab).
Every release from 0.1.0 to 1.0.1 is affected; upgrade to 1.1.1 or later together with
better-auth 1.7.7 (1.1.0 is deprecated: it pins better-auth 1.7.5).

- **SSO sign-in is bound to the signing provider's verified domain.** A JIT user creation and
  every session an SSO callback mints require the provider to be domain-verified for the
  user's e-mail domain; accepting an invitation requires a verified e-mail; `/sso/register`
  requires an organization.
- **Organization sign-in policy is computed from a complete view of the user.** `ssoEnforced`
  and `allowedMethods` apply for every organization with a claim on the user (memberships,
  active organization, verified-domain claims), with upstream's domain-matching rules, and
  sign-in paths the package cannot classify fail closed for users under a restricted
  `allowedMethods`.
- **API keys follow their owner.** A key of a banned or deleted user is refused at use, and new
  keys expire by default. The paths that revoke a user's keys are `/admin/ban-user`,
  `/admin/remove-user`, and a SCIM deactivation, SCIM delete or SCIM connection decommission.
  Revoking sessions, removing an organization membership, or removing a user at the identity
  provider without SCIM does not revoke keys; ban the user or delete their keys. A request
  carrying a key reaches `/get-session` only.
- **Stored IdP secrets are always encrypted on write**, and a field that cannot be decrypted
  affects only its own provider.
- **SCIM decommission is owner-only**, and a SCIM feed never bans a user who holds an owner
  membership.
- **Organization policy settings apply at every enforcement point.** `require2fa` is enforced
  at session creation, on every request and for the owners of API keys, and `sessionMaxAgeS`
  bounds session refresh as well as creation.

## Behaviour changes

Every change is on by default in the plugins the preset mounts; the upgrade guide's
[behaviour table](../upgrading-to-1.1.md#3-behaviour-changes) lists what an integrator sees,
the pre-upgrade check and the opt-out where one exists. The ones most likely to be noticed:

- `require2fa` is enforced at upgrade, without a grace period; apply the data-only migration
  with `ab-enterprise migrate --out <folder> --from 0003` (every 1.0.x install; `--from 0002`
  for a 0.1.x folder that never applied `0002`) and redirect to enrolment on
  `enterprise.enrollmentRequired`. 0.1.x installs first follow `docs/migration-1-7.md`.
- Accepting an invitation requires a verified e-mail.
- New API keys expire after 90 days; a key reaches `/get-session` and nothing else.
- Decommissioning a SCIM connection is owner-only.
- An SSO provider may sign in only addresses of its verified domains; `/sso/register` requires
  `organizationId`; one organization per verified domain (`409 SSO_DOMAIN_TAKEN`).
- Newly audited changes answer `500 AUDIT_WRITE_FAILED` when their audit row cannot be written.
- `samlify` (`^2.13.1`) is a new peer dependency.
- Settings the preset applies to its own plugins do not reach a plugin a product mounts in
  their place: a replaced `organization()` must set `requireEmailVerificationOnInvitation: true`
  itself, and a product's own `apiKey()` mounted instead of, or next to, the preset's drops the
  default expiry and the banned-owner refusal (upgrade guide, step 2).

## Features

- `sso.domainBinding`, `sso.trustVerifiedDomainEmail`, `sso.allowedIssuers` (applied to the
  issuer, every OIDC endpoint and, for SAML, the signing certificates) and
  `sso.samlCertificateFingerprints`. Multi-origin IdPs list every origin they serve endpoints
  from; with an array allow-list, a SAML provider is refused unless its signing certificates are
  pinned, and its `issuer` string (the service provider's id under upstream) must itself match
  an entry.
- `organization.requireEmailVerificationOnInvitation`,
  `organization.allowUserToCreateOrganization`.
- `policy.signInMethods`, `policy.twoFactor.satisfiedBy`, `policy.twoFactor.enrollmentPaths`.
- `apiKeys.defaultExpiresInS`, `apiKeys.maxExpiresInDays`, `apiKeys.enableSessionForAPIKeys`,
  `apiKeys.rateLimit`.
- `audit.chainKey` (HMAC-keyed audit chain), `GET /enterprise/audit/head`, and
  `ab-enterprise audit-verify` with `AB_AUDIT_CHAIN_KEY` and `--expect-head`.
- `ab-enterprise migrate --from <NNNN>`; the command writes every package migration a folder
  does not hold yet and refuses a folder it cannot prove it wrote.

## Audit log

The audit log now records what the documentation describes:

- sign-in, sign-out, failed, refused (`auth.sign_in_refused`, `auth.session_refused`) and
  2FA-pending (`auth.sign_in_2fa_pending`) sign-ins into every organization of the user, with
  the organization resolved server-side;
- role changes, joins and domain verifications attributed to the acting user and filed in the
  organization acted on;
- actions under staff impersonation recorded as `actorType: "impersonated"` with
  `metadata.impersonatedBy`, and impersonation start/stop;
- IdP updates and deletions, `/admin/*`, organization, team, invitation, two-factor, password,
  e-mail, passkey, session-revocation and API-key changes, audit export (`audit.exported`) and
  compaction, organization deletion (`org.deleted`), API-key revocation (`api_key.revoked`) and
  a SCIM ban skipped for an owner (`scim.user_deactivation_skipped`);
- every row bounded; request values that cannot be recorded stored as `(unrecorded)`;
- `/enterprise/audit/verify` answers `{ ok: true, keyed }`.

## Hardening

- The OIDC `trustedOrigins` setting is documented as better-auth's SSRF and redirect
  boundary, not an issuer allow-list (`sso.allowedIssuers` is).
- An unverified provider for another organization's verified domain can no longer be
  registered or verified (`SSO_DOMAIN_TAKEN`), and e-mail `/sign-in/sso` is pinned to the
  verified provider.
- `/sign-in/email` and `/sign-in/magic-link` no longer answer policy errors before the
  credential is checked.
- Sign-in paths the package cannot classify fail closed for users under a restricted
  `allowedMethods` (`policy.signInMethods` names them).
- SSO providers cannot be created without an organization, and changing or deleting one is
  gated on its own organization's `sso` entitlement.
- Organization ids from a request are validated before any query; the entitlement gate checks
  the organization each endpoint acts on.
- Failed adapter queries are logged without their SQL statement or parameters.
- `ab-enterprise migrate` writes `0002` and `0003` as well as `0001`.

## Deprecations

After 1.1.0 is published, 0.1.0, 1.0.0 and 1.0.1 are deprecated on npm with a message pointing
to 1.1.0. 0.1.0 was published without provenance (the documented manual first publish); the
provenance statements of 1.0.0 and 1.0.1 name the commit immediately before the tagged release
commit whose tree was published.
